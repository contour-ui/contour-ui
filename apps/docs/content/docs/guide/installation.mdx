## Requirements

- React 19: a peer dependency of every package; React DOM 19 on the web.
- A bundler that imports CSS from packages: Vite, Next.js, Rsbuild, webpack with a CSS loader.
  The packages are ESM only.
- In a Soundor plugin UI, `@soundor/react` 0.15 and the `soundor` condition: see
  [Soundor plugin UIs](#soundor-plugin-uis).

## Install

Your app imports the token and font stylesheets (and, for Fumadocs, the stylesheet of
`@contour-ui/react`) directly, so list those packages as your own dependencies too: strict package
managers such as pnpm do not expose dependencies of dependencies to your code. Pick your package
manager in any block below: the others follow, and the site remembers it.

**The styled components**, everyday and Audio:

```package-install
@contour-ui/react @contour-ui/tokens @contour-ui/fonts
```

**Headless**, no styles and no tokens:

```package-install
@contour-ui/headless-react
```

**Fumadocs**, a docs site on fumadocs-core:

```package-install
@contour-ui/fumadocs @contour-ui/react @contour-ui/tokens @contour-ui/fonts fumadocs-core fumadocs-mdx
```

A docs site on Fumadocs takes a few more steps: [Setup](/docs/fumadocs/setup) wires it into React
Router or Next.js.

## Load the stylesheets

`@contour-ui/react` styles its components with plain CSS that reads token variables. Import the
stylesheets once, in your app entry, in this order:

```tsx title="main.tsx"
import '@contour-ui/tokens/tokens.css'; // tokens: --ct-* custom properties for every theme
import '@contour-ui/fonts/fonts.css'; // fonts: IBM Plex Sans and JetBrains Mono
import '@contour-ui/react/styles.css';
```

The stylesheets do not import each other, so your app decides what loads and when, and tokens
load once.

`@contour-ui/fonts/fonts.css` declares the font faces the type tokens refer to (SIL Open Font
License), split by script: the browser downloads only the files a page uses. Skip the package if
your app already provides these fonts; the token font stacks fall back to system fonts. It also
holds static TTF files of the same faces for runtimes that register fonts by file.

Headless needs no stylesheet. A docs site on Fumadocs loads `@contour-ui/fumadocs/styles.css`
after the tokens and before `@contour-ui/react/styles.css`, since its first rule sets the order of
the cascade layers ([Fumadocs](/docs/fumadocs#load-the-stylesheets)).

### Cascade layers

Every rule of `@contour-ui/react/styles.css` sits in a
[cascade layer](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer): `contour.components`,
inside the `contour` layer. CSS outside any layer wins over layered CSS whatever its selectors, so
your own stylesheet overrides a component without heavier selectors or `!important`:

```css title="app.css"
/* Wins over the button's own rule: same selector, but not in a layer. */
.contour-button {
  border-radius: 0;
}
```

- **Tokens.** `tokens.css` only defines custom properties on `:root`, outside any layer, so the
  layers do not affect it.

Resets count as your CSS too: a reset loaded outside a layer overrides the components as well.
Give it a layer declared before `contour`:

```css title="app.css"
@layer reset, contour;
@import './reset.css' layer(reset);
```

### With Tailwind CSS

Tailwind CSS v4 puts its CSS in four layers: `theme`, `base` (Preflight, its reset), `components`
and `utilities`. Layers rank in the order they are first declared, the last one strongest, so
declare the whole order once, at the top of the stylesheet that imports Tailwind:

```css title="app.css"
@layer theme, base, contour, components, utilities;
@import 'tailwindcss';
```

`contour` comes after `base`, so Preflight does not strip the components' padding, borders and
backgrounds, and before `utilities`, so a utility class overrides a component, as in
`<Button className="rounded-none">`. Without this line the order follows whichever stylesheet
loads first: if `@contour-ui/react/styles.css` comes first, Preflight resets the components; if
Tailwind's does, utilities cannot override them.

## Page background

Tokens do not style the page itself. Give the document the canvas colors so the space around
components follows the theme:

```css title="app.css"
body {
  margin: 0;
  background: var(--ct-color-bg-canvas);
  color: var(--ct-color-fg-default);
  font: var(--ct-text-body);
  letter-spacing: var(--ct-text-body-letter-spacing);
}
```

## A minimal app

```tsx title="main.tsx"
import { Button } from '@contour-ui/react';
import { createRoot } from 'react-dom/client';

import '@contour-ui/tokens/tokens.css';
import '@contour-ui/fonts/fonts.css';
import '@contour-ui/react/styles.css';
import './app.css';

const root = document.querySelector('#root');
if (root !== null) {
  createRoot(root).render(<Button>Hello, contour-ui</Button>);
}
```

## Soundor plugin UIs

The same packages run in [Soundor](https://github.com/soundor/soundor) plugin UIs, from the same sources:
`@contour-ui/primitive`, under every part, has a build that renders the nodes of `@soundor/react`
(`View`, `Text`, `Pressable`, `Svg`) and turns `role` and `aria-*` into Soundor's accessibility. So
far `Button` and `Knob` run there; the other components follow.

```package-install
@contour-ui/react @soundor/react
```

The bundler and TypeScript pick that build by the `soundor` export condition. Tell TypeScript in
the plugin's `tsconfig.json`:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "moduleResolution": "bundler",
    "customConditions": ["soundor"]
  }
}
```

Soundor 0.15 bundles the UI without that condition, so it takes the web build: until Soundor sets
it, patch the CLI (`pnpm patch soundor`) to pass `inputOptions: { resolve: { conditionNames:
['soundor'] } }` to the build of `bundleUi()`.

Register the fonts before the first render, and wrap the UI in `ThemeProvider` to choose a theme
(the dark one without it):

```tsx title="main.tsx"
import { Button, registerFonts, ThemeProvider } from '@contour-ui/react';
import { render } from '@soundor/react';

void registerFonts();

render(
  <ThemeProvider>
    <Button onPress={save}>Save</Button>
  </ThemeProvider>,
);
```

There are no stylesheets in Soundor: the components draw with the token values of the theme. Their
props are the web's, written for every platform: `onPress` for a press of any kind, `aria-label`
for a name, `style` as Soundor takes it (styles, or a function of the state).
