## Pick a package

contour-ui ships three React packages. Pick by what you build and how much of the look you want to
own:

| Package                      | What you get                                        | Use it when                                     |
| ---------------------------- | --------------------------------------------------- | ----------------------------------------------- |
| `@contour-ui/kit`            | Styled general-purpose components                   | you build an app in the contour-ui look         |
| `@contour-ui/headless-react` | Unstyled components: structure and behavior         | you want contour-ui behavior with your own look |
| `@contour-ui/fumadocs`       | A documentation layout for Fumadocs, built from Kit | you build a docs site on Fumadocs               |

Kit holds both the everyday components and the controls of audio-plugin UIs (the Audio section),
so a plugin needs one package for its whole window. A docs site on Fumadocs shows Kit components
in its pages.

## How the packages fit together

- **Headless** renders the structure and behavior of interactive components (popovers, dialogs,
  listboxes…), with no styles. It also exports `Primitive`, the elements every part renders
  through, so you can build parts of your own.
- **Kit** styles them: an interactive Kit component is its Headless component plus class names
  and the CSS behind them, with the same props. Components without behavior, such as buttons,
  cards and alerts, exist only in Kit.
- **Audio** builds on Kit: its controls reuse Kit parts and add audio-specific styles, such as
  monospace numeric readouts whose digits do not shift while the value changes.
- **Fumadocs** builds a documentation site from Kit on [Fumadocs](https://fumadocs.dev): the
  layout, the search and the components of MDX pages, in place of `fumadocs-ui`. This site runs on
  it, see [Fumadocs](/docs/fumadocs).
- **Tokens** (`@contour-ui/tokens`) are the design decisions as CSS custom properties: colors,
  spacing, sizes, radii, type and motion, for every theme. Kit and Audio styles read them. You load
  `tokens.css` once and can use the same variables in your own CSS, see
  [Styling with tokens](/docs/guide/styling).

All packages are released together under one version: keep their versions equal.

## Anatomy of a component

Each part of a component renders one DOM element. A component made of a single element is a plain
component, such as `<Button>` or `<Kbd>`. A component with several parts is a namespace of parts,
such as `<Card.Root>` with `<Card.Title>` inside:

```tsx
import { Button, Card } from '@contour-ui/kit';

<Card.Root className="session">
  <Card.Body>
    <Card.Title>Session</Card.Title>
    <Card.Description>48 kHz, 24-bit</Card.Description>
  </Card.Body>
  <Card.Footer>
    <Button size="sm">Open</Button>
  </Card.Footer>
</Card.Root>;
```

- Parts accept the props of their element (`className`, `style`, `aria-*`, event handlers, …) and
  pass them through.
- With `asChild`, a part renders its only child instead of its own element and merges its props,
  event handlers and ref into it. Use it to render your router's link in place of an `<a>`, for
  example.
- Every part is marked with `data-scope` (the component) and `data-part` (the part), for example
  `data-scope="card" data-part="title"`. Headless users style with these attributes; in Kit
  and Audio they are stable hooks for tests and overrides.
- Kit and Audio add class names: `contour-<component>` on the root or the single element, and
  `contour-<component>__<part>` on the other parts. Your `className` is merged with them.
- Variants and sizes are attributes next to the state ones: `data-variant`, `data-size`,
  `data-state`. A selector such as `.contour-button[data-variant='solid']` targets one variant.
