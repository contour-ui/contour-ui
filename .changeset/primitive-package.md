Add the element layer: the elements the parts of the components are made of, in web words (`Primitive.div`, `Primitive.span`, `Primitive.text`, `Primitive.button`, `Primitive.svg`, `Primitive.path`, `Primitive.line`, `Primitive.formValue`; `role`, `aria-*`, `tabIndex`, pointer, key and focus events, `onPress`), with a build per platform picked by export conditions. The web build (the default) renders React DOM with the props as they are and `asChild` on every element, and keeps the other DOM elements of the parts (`Primitive.a`, `h2`, `li`, `table`…). The Soundor build (`soundor`) renders the nodes of `@soundor/react` and translates the vocabulary through a compatibility table (`ROLES`, `ARIA_ATTRIBUTES`): roles into `accessibilityRole` (a role without a twin throws), `aria-labelledby` and `aria-describedby` into names and hints through an id registry, `aria-value*` and the states into `accessibilityValue` and `accessibilityState`, `tabIndex` into `focusable` with the DOM's focus fixup, strings into `Text` runs in an ambient `textStyle`. The services read the input the same way on every platform: `useDrag` (a drag of the primary button, the pointer lock, a double press at its second press, which starts no drag), `useWheel`, `useInteraction` (hover, press, focus and `focusVisible` in a store per element, read with `useInteractionField`), `useRangeActions` (the actions of assistive technology on Soundor), `useStyleState` (at rest on the web, live on Soundor), `customProperties`, `PartStyle` and `resolveStyle`, and `registerFont` on Soundor. Also `mergeProps`, `composeRefs`, `useComposedRefs` (moved from `@contour-ui/headless`), `InteractionState` and `NativeStyle`. Peers: `react`; `react-dom` and `@soundor/react`, each optional.
